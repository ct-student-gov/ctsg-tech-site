# Working preferences

- The user wants granular control. Complete only the specific change requested in the current task; do not expand it into a broader project or take adjacent actions on the user's behalf.
- Do not infer authorization for extra features, refactors, redesigns, deployments, commits, pushes, or edits to WordPress from a narrower request.
- If an additional change would be useful but is not necessary for the requested task, mention it briefly and wait for the user to request it. Do not implement it proactively.
- Add pages with plain, unstyled HTML unless the user explicitly requests styling. Do not add CSS, themes, decorative layouts, or visual polish by default.
- Keep changes small and easy to review. Do only the implementation and focused verification needed for the requested change.
- Explain what changed concisely. Avoid turning a small request into a large workflow or a long list of follow-up tasks.
